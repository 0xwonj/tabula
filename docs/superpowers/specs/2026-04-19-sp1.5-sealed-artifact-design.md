# SP-1.5 — `tabula-contract::SealedArtifact`

## 0. Status / Scope

Landing sub-project inserted between SP-4 and SP-5 of the architecture
refactoring umbrella (`docs/superpowers/specs/2026-04-18-architecture-refactoring-design.md`).

Purpose: close SP-1's structural gap by introducing a first-class
`SealedArtifact` in `tabula-contract` and flipping the verifier's public
entry point to `Arc<SealedArtifact>`. This lets SP-5 land with its
intended asymmetric builder signatures without bundling wire-type
relocation into the runtime decomposition.

Out of scope:
- changing proof semantics
- touching compiler policy, IR surface, or chip/machine shapes
- persistence / wire-format backward compat (prototype; clean break)
- expanding `SealedArtifact` to carry `ValidatedProgram` (would force
  `contract → ir`, forbidden by §3 of the umbrella)

## 1. Motivation

The umbrella assigns contract wire-type authority to `tabula-contract`.
§2.1 names `SealedArtifact` among the types contract owns; §2.3 requires
`prepare_verifier` to take `Arc<SealedArtifact>`. Neither has landed:
the type does not exist, and today `prepare_verifier` takes
`RegisteredProgram` (a compiler type that owns `ir::ValidatedProgram`).

If SP-5 runs against the current signatures, every builder surface and
caller (CLI, SDK, examples, tests) gets rewritten once during SP-5 and
again when `SealedArtifact` is introduced. That wastes work and
muddies SP-5's pure-refactor byte-identity gate.

SP-1.5 closes the gap so SP-5's byte-identity gate is clean.

## 2. Target Shape

### 2.1 `tabula-contract::SealedArtifact`

Contract-side sealed artifact carrying all artifact fields the verifier
and runtime preparation consume, plus two seal-time-computed
derivations the runtime used to recompute from IR.

```rust
// crates/contract/src/sealed_artifact.rs
pub const SEALED_ARTIFACT_SCHEMA_VERSION: u32 = 1;

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SealedArtifact {
    pub(crate) schema_version: u32,
    pub(crate) execution_contract: tabula_core::ProgramExecutionContract,
    pub(crate) profile_catalog: tabula_profile::ProfileCatalog,
    pub(crate) tuple_encoding_defaults: TupleEncodingDefaults,
    pub(crate) static_table_artifact: StaticTableArtifact,
    pub(crate) metadata_envelope: ContractMetadataEnvelope,
    pub(crate) binding: ProgramBinding,
    pub(crate) relation_policy: SealedRelationPolicy,
    pub(crate) uses_ir_hash: bool,
}
```

Accessors mirror `RegisteredProgram`'s contract-level getters.

### 2.2 `tabula-compiler::RegisteredProgram`

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct RegisteredProgram {
    pub(crate) artifact_schema_version: u32,
    pub(crate) sealed: SealedArtifact,
    pub(crate) validated: ir::ValidatedProgram,
    pub(crate) capability_manifest: Vec<ir::CapabilityDescriptor>,
}
```

Existing accessors (`execution_contract()`, `binding()`,
`static_table_artifact()`, …) proxy to `self.sealed.<field>()`. IR-side
accessors (`program()`, `validated_program()`, `capability_manifest()`)
stay as-is. A new `sealed()` accessor returns `&SealedArtifact`.

### 2.3 `tabula-contract::SealedRelationPolicy`

The current `runtime::bootstrap::program::RelationPolicy` enum moves
into contract, renamed to make its sealed provenance explicit.

```rust
// crates/contract/src/sealed_relation_policy.rs
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum SealedRelationPolicy {
    Disabled,
    RequireArtifactRoot,
}

impl SealedRelationPolicy {
    pub const fn requires_artifact_root(self) -> bool { … }
}
```

Runtime keeps no local `RelationPolicy` type after T1.

### 2.4 Asymmetric prepare signatures

```rust
pub fn prepare_prover(registered: Arc<RegisteredProgram>) -> Result<PreparedProver, _>;
pub fn prepare_verifier(sealed: Arc<SealedArtifact>) -> Result<PreparedVerifier, _>;
// prepare_executor lands in SP-5 — stays on Arc<RegisteredProgram>.
```

This asymmetry is structural and correct: verifier is IR-free (binding
check + relation/hash chip gating only); prover/executor execute IR.
Making verifier take `RegisteredProgram` would force callers to carry
IR they don't need; making prover take `SealedArtifact` would require
`contract → ir`, forbidden by §3.

## 3. Dependency Audit

`cargo tree` check: `tabula-profile` depends only on `tabula-core`, so
`tabula-contract → tabula-profile` introduces no cycle and no layer
inversion. Resolution: add `tabula-profile` to
`crates/contract/Cargo.toml`. `ProfileCatalog` is contract-layer
semantics (profile = sealed proof-visible metadata), so the dep
direction matches the layer model.

`tabula-contract` transitive set after T3:
`tabula-core`, `tabula-commitment`, `tabula-profile`, plus leaf crates
(`blake3`, `borsh`, `serde`, `sha2`, `p3-*`, `thiserror`). No
`tabula-ir` dep — the §3 forbidden direction is preserved.

## 4. Seal-Time Computations

Both IR-derived bits get computed once at registration time and stored
on `SealedArtifact`:

- **`relation_policy`**: scan `ir::Op::AssertRelation` / `EvalRelation`.
  Today in `runtime/src/bootstrap/program.rs:171-182` (`program_uses_relations`
  + `RelationPolicy::from_program`). Moves into compiler registration.
- **`uses_ir_hash`**: scan `ir::Op::Hash`. Today at
  `runtime/src/bootstrap/program.rs:163-169` (`program_uses_hash`).
  Moves into compiler registration.

Both helpers relocate to `crates/compiler/src/registration/`. Runtime
reads the sealed bits instead of scanning.

Seal-time computation is safe: these bits are pure functions of
`ir::Program`, already fixed at registration, and are part of the
binding transitively (they gate chip selection, and chip selection
shows up in `ProgramBinding` / machine setup).

## 5. Verifier Path Migration

`resolve_program_setup` splits along IR-dependence:

```rust
// bootstrap/program.rs after SP-1.5

pub(crate) fn resolve_sealed_artifact_setup(
    sealed: &SealedArtifact,
    host: &HostEnvironment,
    accepted_root_binding_families: &[RootProfileId],
) -> Result<ProgramSetup, RuntimeError>;

pub(crate) fn resolve_program_setup(
    registered: &RegisteredProgram,
    host: &HostEnvironment,
    accepted_root_binding_families: &[RootProfileId],
) -> Result<ProgramSetup, RuntimeError> {
    // delegate to resolve_sealed_artifact_setup(registered.sealed(), …)
}
```

`ArtifactContext` construction reads only from sealed fields:

```rust
fn artifact_context_from_sealed(sealed: &SealedArtifact) -> ArtifactContext {
    ArtifactContext::new(
        sealed.binding().clone(),
        sealed.execution_contract().program_id, // verified below
        sealed.static_table_artifact().root,
    )
}
```

**Note on `program_id`:** the current code reads `program_id` from
`registered_program.program().program_id`. `ProgramExecutionContract`
already carries a matching `program_id` that is part of the sealed
contract (verified at validation time). The sealed variant reads from
`execution_contract`. T5 includes a sanity check that the two agree on
sample programs (they must, since `program_id` is part of the binding
recomputation).

If investigation during T5 shows `program_id` is **not** currently
stored on `ProgramExecutionContract`, the fix is to add it there as
part of this refactor — the field is a sealed identifier, not IR.

`ResolvedStateRuntime::from_registered_program` already reads only
`execution_contract()` and `profile_catalog()` (verified at
`crates/runtime/src/state_runtime.rs:48-56`). T5 adds
`from_sealed_artifact(&ExecutionContract, &ProfileCatalog, …)` and
rewrites `from_registered_program` as a one-line wrapper.

## 6. Serialization & Schema

- `SealedArtifact::canonical_bytes()` prefixed with
  `"tabula.contract.sealed_artifact.v1"`; payload = `serde_json` of the
  struct (mirrors the existing `RegisteredProgram` pattern).
- `RegisteredProgram::canonical_bytes()` prefix bumps to
  `"tabula.compiler.registered_program.v2"` because the struct layout
  changed (flat fields → `{sealed, validated, capability_manifest}`).
- No persistence compat: the SDK digests a fresh `RegisteredProgram`
  built from source at every invocation; nothing on disk depends on the
  old v1 digest across rebuilds.

## 7. Validation Relocation

- `SealedArtifact::validate()` owns contract-level checks: tuple-encoding
  canonicality, profile hash recomputation, semantic hash recomputation
  (needs `&ir::Program`, so this check stays on the compiler path),
  static-table rebuild, binding recomputation.

  **Split rule:** checks that require only sealed fields live on
  `SealedArtifact::validate()`; checks that require IR stay on
  `RegisteredProgram::validate_sealed_artifact()`.

  Specifically:
  - Tuple encoding canonicality → `SealedArtifact::validate()`
  - Profile hash recomputation → `SealedArtifact::validate()`
  - Metadata envelope compatibility policy check → `SealedArtifact::validate()`
  - Semantic hash recomputation → `RegisteredProgram::validate_sealed_artifact()`
  - Static table artifact rebuild → `RegisteredProgram::validate_sealed_artifact()` (needs `ir::Program`)
  - Binding recomputation → `RegisteredProgram::validate_sealed_artifact()` (needs `ir::Program`)

- `RegisteredProgram::validate_sealed_artifact()` = `self.sealed.validate()?`
  then the IR-requiring checks.

- New error variant `SealedArtifactError` (or reuse
  `ContractValidationError` if it fits).

## 8. Consumers

### Migrate to `Arc<SealedArtifact>`

- `crates/runtime/src/verifier.rs` — builder + `prepare_verifier` flip.
- `crates/runtime/src/bootstrap/program.rs` — split
  `resolve_program_setup`; relocate `RelationPolicy` imports; rewrite
  `artifact_context_from_registered_program` to
  `artifact_context_from_sealed`.
- `crates/runtime/src/state_runtime.rs` — add
  `from_sealed_artifact(&ExecutionContract, &ProfileCatalog, …)`;
  `from_registered_program` delegates.
- `crates/testing/src/runtime.rs` — add `sealed_artifact_from_source`
  helper; `build_verifier` accepts `Arc<SealedArtifact>` (or extracts
  from a passed `RegisteredProgram` for ergonomic test call sites).
- `crates/cli/**` — verifier call sites pass
  `artifact.sealed_artifact().clone().into()` (or similar).

### Stay on `Arc<RegisteredProgram>`

- `crates/runtime/src/prover.rs` (IR-executing).
- `crates/runtime/src/engine.rs` (batch execute).
- Future `crates/runtime/src/executor.rs` (SP-5 — IR-executing).
- `crates/sdk/src/program/artifact.rs` — `Artifact` still wraps
  `RegisteredProgram`; gains `fn sealed_artifact(&self) -> &SealedArtifact`.

## 9. Test Plan

### Unit / crate-local

- `crates/contract/tests/sealed_artifact.rs`:
  - round-trip `canonical_bytes` → `serde_json::from_slice` → struct.
  - `validate()` passes on a known-good fixture.
  - `validate()` fails on mutated tuple_encoding, mutated binding,
    mutated metadata envelope.
- `crates/compiler/tests/sealed_artifact_seal.rs`:
  - program with no relations + no hash → `relation_policy = Disabled`,
    `uses_ir_hash = false`.
  - program with `AssertRelation` → `RequireArtifactRoot`.
  - program with `Op::Hash` → `uses_ir_hash = true`.
  - Combined-op program → both bits set.

### Integration

- Existing runtime + SDK suites all go through
  `register_program_from_source`; no manual struct construction. They
  must all remain green.

### Byte-identity gate

- `cargo run -p tabula-cli -- prove examples/basic` pre- and post-SP-1.5
  produces byte-identical `proof.bin` + `public_statement.json`.
- Same for `examples/membership`.
- Any divergence is a bug: SP-1.5 is a pure wire-type relocation with
  no change to execution, witness, or machine.

## 10. Execution Plan

Tasks execute in order on the existing `sp4-runtime-prepared-handles`
branch (SP-1.5 continues SP-4's branch). Each task is one reviewable
commit.

- **T1** — Relocate `RelationPolicy` → `SealedRelationPolicy` in
  `tabula-contract`. Update runtime imports; compiler gains
  `from_program` helper. Compile clean, tests green.
- **T2** — Introduce `SealedArtifact` struct in `tabula-contract`
  (fields, accessors, `canonical_bytes`, `canonical_digest`,
  `validate()` for sealed-only checks, error type).
- **T3** — Dependency audit (confirmed above: add
  `tabula-profile` to `crates/contract/Cargo.toml`). Verify no cycle.
- **T4** — Split `RegisteredProgram` into
  `{ sealed, validated, capability_manifest }` in compiler. Seal-time
  compute `relation_policy` + `uses_ir_hash` at `register` call site.
  Accessors proxy; `validate_sealed_artifact` delegates. Bump
  `canonical_bytes` prefix to `v2`.
- **T5** — Migrate runtime verifier to `Arc<SealedArtifact>`: builder,
  `prepare_verifier`, `resolve_sealed_artifact_setup`,
  `artifact_context_from_sealed`, `state_runtime::from_sealed_artifact`.
  Verify `program_id` sourcing from `ExecutionContract` (add to
  `ExecutionContract` if missing).
- **T6** — `tabula-testing` updates: `sealed_artifact_from_source`
  helper; `build_verifier` accepts `Arc<SealedArtifact>`.
- **T7** — SDK `Artifact` gains `sealed_artifact()` accessor; wrapper
  remains `RegisteredProgram`.
- **T8** — CLI verifier call-site migration.
- **T9** — Add `contract/tests/sealed_artifact.rs` +
  `compiler/tests/sealed_artifact_seal.rs`.
- **T10** — Byte-identity verification on `examples/basic` +
  `examples/membership`. Document in a short "SP-1.5 Landed" footer on
  this design doc.

## 11. Open Decisions (to resolve inline during execution)

- **`program_id` source on verifier path.** If
  `ProgramExecutionContract` already carries `program_id`, use it.
  If not, add it there as part of T5 (it's a sealed identifier, not IR).
- **Tuple-encoding defaults location.** Already in
  `tabula-contract::format::typed_tuple` — no move needed.
- **`SealedArtifact::validate()` error type.** Prefer a new narrow
  `SealedArtifactError` over widening `ContractValidationError`, but
  if the existing error covers every case, reuse it.

## 12. Success Criteria

- `cargo build --workspace` clean.
- `cargo test --workspace` green.
- `cargo clippy --workspace --all-targets --all-features -- -D warnings` clean.
- `grep -rn "RegisteredProgram" crates/runtime/src/verifier.rs`
  returns zero matches — verifier is a pure `SealedArtifact` consumer.
- `prepare_verifier` public signature takes `Arc<SealedArtifact>`.
- `prepare_prover` public signature unchanged
  (`Arc<RegisteredProgram>`).
- Byte-identical proofs and public statements on `examples/basic` and
  `examples/membership` pre- and post-SP-1.5.
- `cargo tree -p tabula-contract` shows only permitted deps
  (`tabula-core`, `tabula-commitment`, `tabula-profile`).
